apps/AgentTasks, server, tools), grounded in the code as of `8830495` in
`~/Code/apple-mcp`, the uncommitted work in the *live* tree `~/apple-mcp`, and
the production ledger at `~/.config/apple-tasks/apple-tasks.db` (81 dispatches).

Companion to [`roadmap.md`](roadmap.md) (idea ledger, #1–#55) and

#52 (partial), #53 A/B, #55 and the #42 onboarding question remain open
(#28/#30 are watch items).

## 2. Findings

### 2.1 Operational hazards (found in the live system, not just the code)

1. **Diverged trees.** `~/apple-mcp` (what launchd runs) is at `46f6b6f` with
   uncommitted edits: `Audit.swift` (claim/`hasActiveDispatch` block on
   `running` only — the recurrence fix), `Dispatch.swift` (dry-run skip
   reasons), a new `AskAgentTasks.swift` intent, `QueueConsole`/`Intents`/
   README. `~/Code/apple-mcp` is at `8830495` (adds `server/`) and lacks all
   of that. The recurrence fix exists **only** as a working-copy diff on the
   live Mac. `docs/ios-bridge.md` already warns about this; the warning isn't
   enough.
2. **Worktree accumulation.** `~/.config/apple-tasks/worktrees` = **1.0 GB**;
   ledger rows #29, #45, #75 are "gc: kept, unmerged branch pending" and are
   re-reported on every 5-minute pass forever. Nothing surfaces them to the
   human as "deliverables awaiting review", and there is no
   `--discard`/`--reviewed` path.
3. **Log growth.** `logs/dispatch.stdout.log` is **6.4 MB** and unrotated —
   every pass emits the full GC report JSON even when nothing changed.
   `scratch/<id>` dirs are never reaped (roadmap #54 notes this).

### 2.2 Dispatcher correctness (`cli/Sources/AppleTasks/Dispatch.swift`, `Audit.swift`)

4. **Runs unledgered when the DB is unavailable.** `claimDispatch` returns
   `-1` on DB failure (`Audit.swift:217–224`); the caller's `guard let
   ledgerId` accepts it (`Dispatch.swift:628`) and proceeds — `worktrees/-1`,
   `runs/-1.log`, no dedupe, no finish record. Should fail closed.
5. **One tag-save failure aborts the whole pass** (`Dispatch.swift:644–649`
   throws) instead of marking that row `aborted` and continuing.
6. **Reap doesn't kill.** Stale `running` rows become `timeout` and the tag
   flips to `[failed]` (`306–319`), but the orphaned agent process (if still
   alive) keeps running. No `dispatch cancel <id>` either.
7. **`succeeded` blocks re-dispatch forever** in the committed code
   (`Audit.swift:204,222`). Fixed in the live tree by blocking on `running`
   only — but that loses the idempotency the `succeeded` guard provided: an
   agent that exits 0 without completing/untagging is stuck under
   `[dispatched:host]` forever, and if it *does* untag but not complete, the
   task re-runs every pass. Needs a real completion-verification rule (§4 P3).
8. **Prompt travels in argv** (`Dispatch.swift:614`): task notes + attachment
   paths in `ps` output, and `E2BIG` risk on long notes. No stdin/file path.
9. **No ledger schema versioning** — three guarded `ALTER TABLE`s
   (`Audit.swift:51–54`); no `PRAGMA user_version`. `AuditDB` is a singleton
   with no lock (safe only because Phase C is serial by construction).
10. **`add-batch` exits 0** with a non-empty `failed` array.

### 2.3 HTTP server (`server/`)

11. **`POST /v1/triage` passes `--list`** (`HTTPServer.swift:121`) but the
    CLI option is `--inbox` (`Triage.swift:19–20`) → ArgumentParser rejects
    the flag → every triage call with a list fails. Confirmed by reading both.
12. **Live dispatch by default.** `--dry-run` is only added when
    `dryRun == true` (`HTTPServer.swift:100`). MCP defaults the other way.
    A phone client that omits the field launches agents.
13. Run-log route loads the whole file (`111–116`; MCP caps at 256 KB);
    hand-rolled HTTP/1.1 parser has no request-size cap; blocking
    `Process` wait per connection with no concurrency cap; no cancel route.
14. Tests cover bind/auth only; route→argv construction is untested
    (which is exactly where bug 11 lives).

### 2.4 MCP server (`mcp/src/server.ts`)

15. Good: `McpServer.registerTool`, `execFile` argv (no shell), tight zod,
    `outputSchema` + `structuredContent`, excellent descriptions, sane per-tool
    timeouts, dry-run defaults on `dispatch_run`/`github_sync`/`triage_inbox`.
16. Missing: **tool annotations** (`readOnlyHint`/`destructiveHint`/
    `idempotentHint`) — none; **resources/prompts** — none; **tests/
    typecheck** — none (no `tsconfig.json`); exit codes not surfaced;
    ~50 copies of `try { okJson(await cli()) } catch { fail() }`.
17. Not exposed: `remirror-tags`, `dispatch --reap-hours/--no-gc`,
    `--no-native-tags`, `--mirror-tags`. `cli/README.md` says 35 tools; the
    server registers 51.

### 2.5 App (`apps/AgentTasks/`)

18. App Intents call `CLI.run` with **no timeout** (`Intents.swift:70–113`) —
    a hung CLI hangs Siri/Shortcuts.
19. `DispatchesTab` never observes `refreshToken`; Activity/Dispatches use
    `guard !isLoading` and drop refreshes (Queue fixed this with

20. Stamped absolute CLI path (`build.sh:48`) + ad-hoc signing → non-portable

21. Missing surfaces users expect: menu bar item, local notifications for

### 2.6 Code structure

### P2 — Dispatcher fail-closed, pass resilience, reap-kill, cancel, prompt transport, hygiene (M)

**Goal.** No path runs an agent without a ledger row; one bad task can't
abort a pass; reaping actually stops processes; a human can cancel; prompts
don't leak via `ps`; logs and scratch dirs stop growing.

**Files.** `Audit.swift`, `Dispatch.swift` (→ see P9 split), `Commands.swift`
(`dispatch cancel`, `dispatch --quiet`), `mcp/src/server.ts`
(`dispatch_cancel`), `server/` (`POST /v1/dispatch/{id}/cancel`),
`tools/launchd/run-with-env.sh`, `tools/launchd/com.apple-tasks.dispatch.plist`,
`docs/auditdb-inventory.md`, `docs/dispatcher-v2.md` (append "v3" section).

**Steps.**
1. **Fail closed.** `claimDispatch` returns `enum ClaimResult { case
   claimed(Int64), held, unavailable }`. Caller: `.held` → silent continue
   (as today), `.unavailable` → report `"skipped: ledger unavailable — not
   dispatching unledgered"` and continue; **never** proceed. Audit-inventory
   doc updated. Same treatment for `finishDispatch`/`setDispatchPaths` when
   `db == nil` (return Bool; log to stderr).
2. **Continue, don't throw.** Tag-save failure after claim → `finishDispatch(
   status:"aborted")` + report `"aborted: could not save claim tag: <error>"`
   + `continue`. Audit row recorded.
3. **PID registry (Phase B is AuditDB-free by design, so use files).**
   `execute()` writes `runs/<ledgerId>.pid` (`pid\nstartedAt`) right after
   `process.run()`, deletes it on exit. Reap: for each stale row, read the
   pid file; if the process exists (`kill(pid, 0) == 0`) *and* `ps -o
   command= -p pid` contains the ledger id or task id (guard against PID
   reuse) → SIGTERM, 5 s, SIGKILL; report `"reaped: killed pid N"`. Also
   reap `.pid` files whose row is already finished.
4. **`dispatch cancel <ledgerId>`** (new subcommand): same kill path; ledger
   status `cancelled` (new value — update `dispatches --status` enum, MCP
   schema, app filter chips); shed *our* claim tag but do **not** write
   `[failed]` (a cancel is not a failure; no retry). Trailer appended. MCP
   `dispatch_cancel` (destructiveHint) + HTTP route. Doctor `--enqueue-heals`
   unaffected.
5. **Prompt transport.** Per-agent `"promptVia": "argv" | "stdin" |
   "file"` (default `argv`, unchanged). `stdin`: argv keeps `{prompt}`
   placeholder removed; `process.standardInput = Pipe()`; write prompt, close.
   `file`: write `runs/<id>.prompt.md`, substitute `{promptFile}` in the
   template. Verified defaults to ship in `examples/agents.json`: `claude`
   → `stdin` (`claude -p` reads stdin when no positional prompt), `cursor`
   → leave `argv` until verified. Run-log header records `promptVia` and
   prompt byte count instead of the argv-joined command when not argv.
6. **Hygiene.** `dispatch --quiet`: emit `[]` when every report is a repeat
   of the previous pass's GC/skip output (compare against `state` KV
   `dispatch.lastReportHash`); launchd plist adds `--quiet`.
   `run-with-env.sh` rotates `logs/*.log` > 5 MiB (`mv x x.1`, keep one).
   Scratch reaper in the GC phase: `scratch/<id>` for finished rows older
   than `keepFailedWorktreeDays` → removed.
7. **Schema version.** `PRAGMA user_version`: 0 → 1 migration wraps the three
   `ALTER`s and adds `dispatches.pid INTEGER` (informational) and
   `dispatches.task_modified_at TEXT` (for P3). Future migrations are a
   switch on version. `AuditDB` gets a private serial `DispatchQueue`
   around every statement (cheap insurance).

**Verify.** Unit (P4): claim on a closed DB → `.unavailable`; race → one
`.claimed` one `.held`. Live with echo lanes (`examples/`-style temp
config): (a) `chmod 000 apple-tasks.db` → dry run passes, live run reports
"ledger unavailable" and spawns nothing; (b) `sleep 600` agent with
`--reap-hours 0.01` → next pass kills it, row `timeout`; (c) `dispatch cancel
<id>` mid-run → process gone, status `cancelled`, tag shed, no `[failed]`;
(d) `promptVia: stdin` echo lane (`cat`) logs the prompt; `ps` shows no
notes text; (e) three `--quiet` passes → `dispatch.stdout.log` grows by
`[]\n` only.

**Risks.** PID reuse (mitigated by command-line check). `claude -p` stdin
behavior across versions — verify once, document. `cancelled` status is a
new enum value every consumer must accept (grep `"timeout"` for the list).

### P3 — Completion verification and deliverable review (M)

**Goal.** Resolve finding 7 properly: re-dispatch is allowed when the *task*
changed (recurrence roll, human edit) and blocked when nothing changed since
our last successful run; and the human sees "branches awaiting review".

**Files.** `Audit.swift` (`task_modified_at`, `verification`), `Dispatch.swift`
Phase A/C, `Commands.swift` (`dispatches --pending-review`, `dispatch gc
--discard <id>`), `Digest.swift`, `apps/AgentTasks/Sources/OpsConsole.swift`
(Dispatches tab), `mcp/src/server.ts`, `docs/dispatcher-v2.md`.

**Design.**
- Phase C, on any finish: after the trailer/notes write-back, re-fetch the
  reminder and store `task_modified_at = reminder.lastModifiedDate` and
  `verification = completed | open-untagged | open-claimed` on the row.
- Phase A guard replaces "block on `succeeded`": block iff the latest
  `succeeded` row for this task has `task_modified_at >=
  reminder.lastModifiedDate` (nothing changed since we last touched it).
  A recurrence roll or a human edit bumps `lastModifiedDate` → eligible.
  An agent that exited 0 and walked away → blocked (idempotent), and the
  dry-run reason says so.
- `open-claimed` after `succeeded`: shed our claim tag in Phase C (the
  process is gone; leaving `[dispatched:host]` strands the task) and append
  `"agent exited 0 without completing"` to the trailer. Blocked by the rule
  above, so no loop.
- Rows with `worktree != NULL`, status `succeeded`, branch unmerged →
  `dispatches --pending-review` (and `--status pending-review` alias);
  digest gains a "Branches awaiting review" section with `git log
  --oneline base..branch | head -3` each; app Dispatches tab shows a
  **Review** badge + "Open in Terminal" (`open -a Terminal <wt>`) + "Discard"
  (→ `dispatch gc --discard <id>`: `worktree remove --force`, `branch -D`,
  `clearWorktree`, audit row). Merged branches keep auto-GC'ing.

**Steps.** (1) migration v2 columns; (2) Phase C write-back; (3) Phase A rule
+ dry-run reason; (4) `pending-review` query + CLI/MCP/HTTP; (5) digest
section; (6) app badge/actions; (7) `--discard`; (8) doc.

**Verify.** Spike first (30 min): does iCloud sync bump
`EKReminder.lastModifiedDate` without content change? Complete a task on the
phone, read `lastModifiedDate` on the Mac before/after an unrelated sync. If
it churns, fall back to comparing `dueDateComponents` + title + notes hash
stored at finish (`task_fingerprint`). Then live: recurring echo task → run,
complete → rolls → next pass eligible; non-recurring echo lane that exits 0
without completing → tag shed, next pass "skipped: unchanged since
succeeded #N"; edit the title → eligible. Discard #29/#45/#75 (after the
human looks at them) and confirm `worktrees/` shrinks.

**Risks.** `lastModifiedDate` semantics (spike covers it). Changing the
guard touches the busiest code path — land behind `"claimGuard": "modified"
| "running"` in `agents.json` for one week, default `modified` after.

### P6 — App: menu bar, pause, notifications, fixes (M)

**Goal.** The human loop gets a glanceable surface and a big red pause
button; Siri can't hang; the console refreshes correctly.

new `MenuBarView.swift`, `LedgerWatcher.swift`, `Notifications.swift`;

`cli/Sources/AppleTasks/Commands.swift` + `Dispatch.swift` (`dispatch
pause/resume`, honor `dispatch.pausedUntil`); `Doctor.swift`; `mcp`.

**Steps.**
1. **Pause (CLI first).** `dispatch pause [--for 2h | --until <ISO>]`,
   `dispatch resume`, `dispatch status` → state KV `dispatch.pausedUntil`.
   `dispatch` exits early with `{"paused": true, "until": …}`; `--reap-only`
   still runs (reaping while paused is desirable). `digest` ignores pause. Doctor reports it. MCP `dispatch_pause`/`resume`
   (not destructive).
2. **MenuBarExtra** (`.menuBarExtraStyle(.window)`): open `[auto]` count,
   running count with agent names, last pass time + result, "Pause 1h / 2h /
   until 7am / Resume", "Dry run now", "Open Console", pending approvals
   count (from `approve list --status pending`). Data via a `LedgerWatcher`
   that polls `dispatches --status running --limit 20` + `approve list` every
   30 s while the popover is open, every 2 min otherwise, plus
   `DispatchSource.makeFileSystemObjectSource` on `apple-tasks.db-wal` for
   immediacy.
3. **Local notifications.** `UNUserNotificationCenter` on: new `failed`/
   `timeout`/`cancelled` row (title = task title, body = trailer, action
   "Open log"), new pending approval (actions "Approve"/"Deny" → `approve
   answer <token>` — Mac-side answer path already exists and is audited),
   `pending-review` count increases (P3). Preference toggles stored in

4. **Fixes.** `CLI.run(timeout:)` default 30 s for intents (60 s for
   `TriageInboxIntent`, 120 s for `AgentStatusIntent`); `DispatchesTab`

   pattern; `AuditEvent.id` = stable hash of `(ts, command, taskId, detail)`;

   `security create-certificate`-equivalent / documented Keychain Access

   `apple-tasks-private` so TCC/Keychain grants survive rebuilds (also a P7
   prerequisite).

**Verify.** Pause → next launchd pass logs `paused`; menu shows state; a

### P7 — Secrets hardening (M; gate for roadmap #16 / publishing)

**Goal.** Secrets can live in the login Keychain; plaintext remains a warned

**Steps.**

   name; `set` reads from `--stdin` or an interactive prompt (never argv);
   `kSecAttrAccessibleAfterFirstUnlock`-class item, `kSecUseDataProtectionKeychain`
   false (login keychain so launchd can read it after login).
2. Resolution in consumers: `xEnv` (env var) → `xKeychain` (item name) →
   `x` (plaintext) → error. Apply to `llm.apiKey`, `notify.topic`,

3. `doctor.secrets`: per-secret `source: env|keychain|plaintext|missing`,
   file modes not `600`, `credentials.json` chmod fix-it.
4. `docs/security.md`: threat model (single user, own Mac, dispatched agents

signing prerequisite. Gmail token migration must keep the rotation logic

## 5. Assessment of the `polish.md` bets

| Idea | Take | When |
|---|---|---|

Cheaper first step: honor each agent CLI's own sandbox flags (`agent --sandbox enabled`, `claude` permission modes) per lane and record the sandbox posture in the ledger/trailer; then a `container`/`tart` lane as an `agents.json` template with a patch-export post-step. | After P2–P4 |

| iCloud Drive distributed locks | Only one Mac dispatches today; hostname-scoped tags already make claims attributable. Skip until a second dispatcher exists. | Not now |
